# 术语表

翻译同一个领域的论文时，术语一错就全篇都错，而且**错得一致** ——
「nanocapsule」这一篇译成「纳米胶囊」、下一篇译成「纳米微囊」，读者就得自己对齐。

这个功能让你维护一份固定的对照表，翻译时强制遵守。

---

## 为什么不是「自动抽取」

pdf2zh 有 `--auto-extract-glossary`：让模型先通读全文抽术语，再翻译。
听起来更好，但它是**第二遍全文档 LLM 调用** —— 请求量直接翻倍。

在本项目这种按会话限流的免费池上，实测后果是**连续 51 个失败任务**，
所以 `auto_glossary` 默认关闭。

**静态术语表是另一回事**：一个 CSV，零额外请求，pdf2zh 只在翻译时查表。
想要术语一致性又不想撞限流，用这个。

---

## 格式

一个 CSV，第一行是表头，必须有 `source` 和 `target` 两列，
第三列 `tgt_lng` 可选（限定该词条只对某种目标语言生效）：

```csv
source,target,tgt_lng
nanocapsule,纳米胶囊
tannic acid,单宁酸,zh-CN
metal-organic framework,金属有机框架
```

- **文件名就是术语表的名字**（`agrochemical.csv` → `agrochemical`）
- 大小写敏感与否取决于 babeldoc，建议按原文的常见写法录入
- 空行、缺 target 的行会被跳过，不算错误

---

## 配置

```json
"translate": {
  "glossaries": [
    "D:\\workbuddy2api\\data\\glossaries\\agrochemical.csv"
  ]
}
```

多个文件用数组列出，程序会拼成逗号分隔的单个参数（pdf2zh 的约定）。

**路径里不能有逗号** —— 逗号是 pdf2zh 的分隔符。含逗号的路径会在提交时被拒绝，
并提示改名，而不是让 pdf2zh 把一个路径切成两半后报「文件不存在」。

---

## 启动时会自检

网关启动时逐个校验术语表并写日志：

```
[translate] 术语表 agrochemical.csv：3 条词条
[translate] 术语表 typo.csv 不可用：文件不存在（该表忽略，翻译照常）
```

**坏表不会让翻译失败**，只会被忽略 —— 这是刻意的取舍：
术语表是可选增强，配错它不该让整个功能停摆。但它必须**立刻说出来**，
否则用户会以为术语表在生效。

能识别的问题：

| 问题 | 报什么 |
|---|---|
| 文件不存在 | 文件不存在 |
| 传了目录 | 这是一个目录，不是 CSV 文件 |
| 扩展名不是 .csv | 扩展名不是 .csv —— babeldoc 只解析 CSV 术语表 |
| 文件过大（>8 MB） | 文件过大（N MB），术语表应远小于此 |
| 表头缺列 | 表头必须含 source 和 target 两列 |
| 没有有效词条 | 表里没有有效词条 |

---

## 一个建议

**从三五条开始，别一上来就建大表。**

术语表的价值在于「反复出现的、译错了很贵的」词 —— 通常是领域专名、材料名、
方法名。把一篇论文里出现二十次的三个词固定住，比录入五百个生僻词有用得多。
