## 三、这一轮新引入的问题（按严重度）

### 🔴 1. 翻译引擎核心逻辑 0% 覆盖

`internal/translate` 总覆盖 **19.2%**，而这 19.2% 全部来自我写的 `persist.go`。
真正承载实测知识的函数**一个都没测**：

| 函数 | 覆盖 | 它承载的是什么 |
|---|---|---|
| `buildArgs` | **0%** | **全部实测参数**：`--no-auto-extract-glossary`（否则 429 风暴）、`--ignore-cache`（否则 A/B 无效）、qps、`--no-mono` |
| `parseTokenTotal` | **0%** | **静默失败检测**：0 token → `partial` |
| `findDualPDFs` | **0%** | 决定 `produced_nothing` 是否触发 |
| `Submit` | **0%** | 校验、幂等去重、`skip_existing` |
| `runOne` | **0%** | 任务状态机 |
| `Cancel` | **0%** | **我修过的双重解锁 bug 的现场** |
| `withNoProxy` | **0%** | **头号实测陷阱**（代理劫持回环请求） |
| `CJKCount` / `MarshalJob` / `LastLine` | **0%** | 质量度量 / 输出形状 |

**后果是具体的**：如果哪天有人（或我）从 `buildArgs` 里删掉
`--no-auto-extract-glossary`，测试全绿、翻译照常跑，但会退回那个**连续 51 个
失败任务**的状态。这个仓库里所有「注释写得比代码长」的地方，恰恰都是没测的地方。

### 🔴 2. 修好的流水线没上线（已修）

复审时发现**本地领先远端 3 个提交**，其中包括修 `update_link` 的那个。
也就是说：我手动把线上 `update.json` 修对了，**但生成它的机器还是坏的** ——
下一次打 tag 会重新生成一份指向 404 的清单。

这类「验证了产物、没验证生成产物的东西」是同一模式的第二次出现
（上一次是「修好了前端但浏览器在跑缓存的旧 JS」）。

已推送，远端 workflow 现在确实带 `--tag`，本地/远端 SHA 一致（`91c3fae`）。

### 🟠 3. 公开仓库历史里有约 57 MB 构建产物

```
d46c6479  13.3 MB   wb2api.exe~
15cfa583  11.9 MB
606f4f1f  11.9 MB
37cd8c1c  11.8 MB
e3426a93   8.0 MB
```

其中 13.3 MB 那个是**我误提交又删掉**的。删掉文件不等于从历史里去掉 ——
公开仓库现在带着它们。对一个源码仓库这是不必要的体积，且 `-s -w` 剥离后的 exe
只有 9.4 MB，五个版本等于把发布物在历史里存了五遍。

**修法**（未做，需要你同意）：`git filter-repo` 重写历史 + 强推。代价是所有
SHA 变化，已发布的 v1.13.0 tag 要重建。**不建议现在做** —— 收益是体积，代价是
破坏已发布版本的引用完整性。等下次大版本时一起处理更划算。

### 🟡 4. `docker-ghcr` 在往 ghcr.io 推容器镜像

仓库继承的 `.github/workflows/docker-ghcr.yml` 在每次打 tag 时**成功推送了镜像**。
你没要求过这个，它也不是「单一软件」的一部分 —— 但它是公开的，任何人可以拉。

**要么保留**（多一个分发渠道，无害），**要么删掉**（少一条与你无关的发布路径）。
我倾向删：一个不打算支持的产物，发布出去就是承诺。

### 🟡 5. 面板覆盖率 11.1%，我加的 9 条测试对数字贡献很小

那些断言是**静态文本分析**（扫 `$('id')`、扫 `DATA-*`、扫未定义调用），
不进覆盖率统计。但它们挡住了这一轮真实的 5 个 bug（变异 8/8 证明了）。
**这是正确的取舍** —— 覆盖率数字低不等于没价值，要区分开说。

## 五、我的判断

**该做的下一件事不是加功能，是给 `internal/translate` 补测试。**

理由不是「覆盖率好看」，而是：这个包里每一个 0% 的函数，都是一次**真实事故**的
修复现场。它们的注释写着「实测代价：51 个连续失败任务」「实测代价：byte-identical
文本」—— 而**没有一条断言在守着它们**。

具体该补的顺序（按「坏了会不会静默」排）：

1. `buildArgs` —— 断言那些参数在（删掉任何一个都是静默退化）
2. `parseTokenTotal` —— 0 / 非 0 / 格式变化三种输入
3. `findDualPDFs` —— 同名前缀、上次残留、大小写
4. `withNoProxy` —— 已有 NO_PROXY 时是追加不是覆盖
5. `Submit` 的校验与幂等 —— 非 PDF、路径不存在、同源在飞
6. `Cancel` 的状态 —— 排队中 / 运行中 / 已终态

前四条加起来大约 120 行测试，能守住这个仓库里最贵的四块知识。
